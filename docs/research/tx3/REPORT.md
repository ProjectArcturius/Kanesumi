# tx3 真 Win10 截图分析 —— 报告（2026-10-04）

> 任务 `tx3-win10-analysis`（GLM 手动执行）。只测量分析、不改代码与既有文档。
> 输入：`tx1/win10/` 下 4 张 BMP（用户提供，代替任务书预期的 PNG）；Ether 对照：`tx2/rust/`
> 的 base / med / med-cg / ol15-cg 四档联系表。所有结论以读图 + 量化交叉验证。

## 一、结论先行

1. **「Win10 的浓郁锐利」不是 UWP 正文给的。** 设置（UWP / DirectWrite）是**纯灰度抗锯齿**
   （彩边占比 0.0%，7 个区域全 0），无 hinting 迹象，边缘 10–90 过渡宽 1.1–1.5 px，
   比 Ether 拟定的 med-cg（0.83）**更软**；且正文、说明文字只有 **60% 黑**（RGB 102,102,102）。
2. **锐利来自 GDI / ClearType**（资源管理器）：彩边占比 0.86–1.0（真亚像素），竖画整数宽、
   网格对齐，边缘过渡 0.87–1.34 px，是四张截图里唯一「强劲锐利」的路径。Win10 自己内部
   GDI 与 UWP 的差距，比 Ether 与 Win10 UWP 的差距更大。
3. **墨量上 Ether 现状并不输 Win10 UWP 正文。** 同字符串「网络和」：Win10（YaHei Regular，
   125%）覆盖率 0.331；Ether base（Noto Regular）1× 0.332 / 2× 0.344。当前裁定 G-67
   （med-cg）0.439，比 Win10 正文高 **+32%**——方向与 Win10 相反：Win10 是「正文淡、节头浓」
   （节头纯黑 + 20px SemiBold ≈ Ether med/med-cg 的浓度）。
4. **参数建议（§六）**：若目标是「像 Win10」，浓度应放层级（节头/标题纯黑 SemiBold）而非
   正文；med-cg 会比 Win10 正文明显更浓，是否保留属用户偏好。2× 不值得做亚像素（Win10
   UWP 在 150% 就是灰度）；1× 亚像素有 GDI 证据支持。

## 二、输入核对

- 4 张 BMP 均为 **1920×1080、24 位、BI_RGB 未压缩**真 BMP（文件大小 6 220 854 B =
  1920×1080×3+54）。用户以 BMP 代替 README 要求的 PNG：BMP 无损，保真只高不低，可接受。
- **JPEG 痕迹检查**：全图 8×8 块边界差分 / 非边界差分比值 ≈ 1.0（四图水平 0.91–1.19、
  垂直 0.92–1.15），无块状压缩痕迹；GDI 文字亚像素彩边完整（§三）→ 未经历任何有损环节，
  可当原图。
- 命名与 README 规则不同（中文名、`.bmp`），内容对应：`设置页-125%` = 设置主页；
  `设置页内容物-100%/-150%` = 「系统 > 显示」页两种缩放（页面下拉框即显示 100% / 150%，
  同页面同文案，互为缩放对照）；`文件管理器-150%` = GDI 资源管理器叠在显示页上。
- 全部为浅色主题。深色主题无 Win10 实物，Ether 深色档无从对照（§七）。
- 截图机：1920×1080 物理分辨率（约 141 PPI），Ether 目标机 3072×1920@2×（251 PPI），
  观看尺寸差异见 §七。

## 三、渲染方式判定

方法：文字区放大看图 + 边缘像素（覆盖率 15–85%）通道散度统计（`txlib.fringe_stats`，
阈值 24/12 级，前后景均为中性灰时彩边 = 亚像素证据）。

| 路径 | 区域 | 彩边占比(>24) | 判定 |
|---|---|---|---|
| UWP（设置） | 100% 正文/节头/标题/下拉、125% 主页标题/导航/说明、150% 全部（共 18 区） | **全部 0.0%** | 灰度抗锯齿 |
| GDI（资源管理器） | 文件名行 ×2 | **1.00** | ClearType 亚像素 |
| GDI | 导航「桌面」/ 列头 | 1.00 / 0.96 | ClearType 亚像素 |
| GDI 宿主 | 搜索框「在 pack 中搜索」 | 0.0 | 灰度（该控件走 DirectWrite，非 GDI 文本路径） |

可视化：`work/z_gdi_chroma8x.png`（色散放大图，橙/蓝彩边清晰）；UWP 任意区域放大无彩边
（`work/z_w100_hdr6x.png`、`z_w150_hdr4x.png`）。

补充观察：UWP 边缘过渡宽（10–90%）1.12–1.51 px（natural 布局，笔画不贴网格）；GDI 文件名
0.87 px 且竖画中位宽恰为整数 2 px（18 px 字号）——ClearType 网格对齐的特征。
中灰分布（边缘像素覆盖率五档，0.05–0.2/0.2–0.4/0.4–0.6/0.6–0.8/0.8–0.95）：

| 样本 | 分布 | 边缘中位 cov |
|---|---|---|
| Win10 UWP 100% 正文 | 0.141 / 0.256 / 0.326 / 0.124 / 0.153 | 0.464 |
| Win10 UWP 150% 正文 | 0.158 / 0.240 / 0.317 / 0.158 / 0.127 | 0.464 |
| Win10 UWP 150% 节头 | 0.107 / 0.285 / 0.320 / 0.215 / 0.073 | 0.463 |
| Ether 2× base | 0.203 / 0.190 / 0.215 / 0.193 / 0.199 | 0.502 |
| Ether 2× med-cg | 0.151 / 0.207 / 0.221 / 0.265 / 0.157 | 0.529 |

即 **Win10 UWP 没有向浓推的 gamma / 对比度补偿**（中位 0.464，还略偏淡）；Ether base 是
教科书式线性灰度 AA（近均匀，0.502）；med-cg 的补偿把边缘像素推向深侧（0.529），
比 Win10 UWP 更「冲」。

## 六、参数建议（每条附依据）

1. **「浓郁」的构成排序**（按测量影响降序）：
   ① **层级排印**：正文 60% 黑 Regular、节头纯黑 SemiBold、标题大字号——浓在节头不在正文
   （§四前景色 + 节头 SemiBold 证据）；
   ② **GDI 的网格对齐 + 亚像素**：e1090 0.87、整数竖画、彩边 100%（§三）；
   ③ **字体设计**：YaHei 满字面、小字号笔画丰满（「网络和」墨量 ≈ Noto，但「个性化」更瘦，
   方向不一致，说明设计取向不同而非全面更浓）；
   ④ **gamma / 对比度补偿：UWP 没有**（中位 cov 0.464 偏淡，§三表）——Windows 的浓不靠这个。
2. **对 G-67（正文 Medium + contrast 0.5 / gamma 1.4）的校准意见**：med-cg 正文墨量比
   Win10 正文高 +32%、边缘（0.83）比 Win10 UWP（1.44–1.51）锐——**它实现的是「比 Win10
   更浓」而非「像 Win10」**。是否保留属用户观感裁定；若以 Win10 为基准，更贴近期望的组合
   是「正文 Regular/med 二选一 + cg 补偿 + 节头/标题层加浓（纯黑 + SemiBold）」。
   注意：以上全部基于浅底；深底无 Win10 实物。
3. **2× 不做亚像素**：Win10 自己的 UWP 主路径在 150% 高缩放下就是灰度（0% 彩边），
   亚像素只存在于 GDI 旧路径——维持 DECISIONS §63 的 scale 分支正确。
4. **1× 保留亚像素 + 网格对齐选项**：GDI 证据（0.87 px 过渡、整数竖画）说明小字号 + 低
   PPI 下「对齐网格」的锐利收益真实存在；对应 Ether 1× 旧机型分支（原 P1b）。
5. **hinting**：UWP 无 hinting 也达到了用户可接受的观感（其软来自 60% 黑而非笔画模糊），
   Ether 2× 下 hinting 维持低优先（DECISIONS §63 路线不变）；1× 的收益以 GDI 为旁证，
   维持「P4 再评估」。
6. **层级建议落地参考**：Ether 已有 20/28 档；Win10 节头 SemiBold 在 30 px em 的墨量
   （本测「缩放与布局」行）≈ med/med-cg——若正文维持 Regular + cg，节头用 Medium/SemiBold
   即可复刻 Win10 的浓度分层，无需正文额外加浓。

## 七、不确定之处

- **字体不同**（YaHei UI / Segoe UI vs Noto Sans CJK / Source Sans）：同字符串墨量可比，
  但「字体设计 × 渲染」不可分离；笔画宽度比较（stem/em）受字形结构影响，只作量级参考。
- **缩放倍率无完全匹配**：Win10 有 100%/125%/150%，Ether 样张 1×/2×。同 em 对照用
  100%↔1×（15 px em）与 150% 20px↔2× 15px（30 px em）两组；125% 仅用于同字符串墨量
  （覆盖率对面积极近似缩放不变，但 18.75 px 物理字号与两侧都不同）。
- **PPI 与观看尺寸**：截图机 141 PPI（150% 下正文 em ≈ 4.0 mm），Ether 目标机 2× 后
  125 逻辑 PPI（15 px em ≈ 3.0 mm）——Win10 正文看起来更大更稳，部分是物理尺寸差异，
  不是渲染差异。
- **主页大标题 24 px 与说明 12/13 px 为反推值**（YaHei 字面比按同图自洽估计 ±8%）。
- **深色主题无实物**，全部结论只覆盖浅底黑字；深底白字的浓度策略仍以 tx1/tx2 样张为准。
- GDI 列头的覆盖率 / 墨量数字受其偏蓝前景影响，仅边缘 / 彩边数字可信。
- Ether 侧样张沿用 tx2 产出（Pillow 读 PNG），未重新渲染；若 tx2 之后样张管线有变，
  需同步重测。
