```
308:       <SolidColorBrush x:Key="SystemControlHighlightChromeWhiteBrush" Color="{StaticResource SystemChromeWhiteColor}" />
```

所以：`Highlight*` = 笔刷别名（供控件模板按语义选用），`SystemList*` = 唯一真值。改 `SystemList*Color` 即同时改 `Highlight*` 与 `BackgroundList*`、`ForegroundList*`、`DisabledListMedium`。

高对比下这一族被**统一压平成单一系统色**（`A:2064`/`A:2065`），Low/Medium 之分消失：
```
2064:       <SolidColorBrush x:Key="SystemControlHighlightListMediumBrush" Color="{ThemeResource SystemColorHighlightColor}" />
2065:       <SolidColorBrush x:Key="SystemControlHighlightListLowBrush" Color="{ThemeResource SystemColorHighlightColor}" />
```

**UWP 确实"按控件取值"，但依据是控件复用不同令牌，不是同一令牌有多个值。** 源 A 的消费侧证据（源 B 无这些转发，只在源 A）：
- AppBar 类 → `HighlightListLow`（10%）与 `HighlightListMedium`（20%）：`A:1680`（`AppBarButtonBackgroundPointerOver`）、`A:1681`（`...Pressed`）、`A:693`/`A:694`（`AppBarEllipsisButton`）
- ListView / GridView 行 → 同样只用这两个：`A:1783`（`ListViewItemBackgroundPointerOver` → ListLow）、`A:1784`（`...Pressed` → ListMedium）
- **不存在**"ListView 行 = 白 30%" 的第三个值（见第 3 节 D2）。

## 第 3 节：矛盾与发现

### D1 —— `SystemBaseMediumHigh` 不是 90%，是 **80%**（alpha 字节 `CC`）

常见说法/本库注释作「BaseMediumHigh 白 90%」，一手源为 **`#CC`**：

```
210:       <Color x:Key="SystemBaseHighColor">#FFFFFFFF</Color>
211:       <Color x:Key="SystemBaseLowColor">#33FFFFFF</Color>
212:       <Color x:Key="SystemBaseMediumColor">#99FFFFFF</Color>
213:       <Color x:Key="SystemBaseMediumHighColor">#CCFFFFFF</Color>
214:       <Color x:Key="SystemBaseMediumLowColor">#66FFFFFF</Color>
```

`0xCC` = 204 → `204/255 = 80.0%`。亮色 `A:4129` `#CC000000` 同为 80%。
**全套档位：High 100% / MediumHigh 80% / Medium 60% / MediumLow 40% / Low 20%。** 等距 20 点，无 90% 档。
本库 `kanesumi-core/src/indicator.rs:53`「BaseMediumHigh（白 90%）」与 `indicator.rs:61`「最接近的 `BaseMediumHigh` 是 0.9」**均与一手源冲突**；正确的 BaseMediumHigh = **0.80**。

### D2 —— `SystemListLowColor` 不是 30%，是 **白 10%**（alpha 字节 `19` = 9.8%）

```
228:       <Color x:Key="SystemListLowColor">#19FFFFFF</Color>
229:       <Color x:Key="SystemListMediumColor">#33FFFFFF</Color>
```

`0x19` = 25 → `25/255 = 9.8%`；`0x33` = 51 → **20%**。
本库 `kanesumi-core/src/indicator.rs:26`「ListView 行是 ≈白 30%（§215）」与 `kanesumi-controls/src/list.rs:109`「HighlightListLow ≈30% 白」**均与一手源冲突**。一手源里 ListLow 只有一个值 = 9.8%，没有按控件分档的 30% 变体。
`kanesumi-controls/src/command_bar_flyout.rs:216`「HighlightListLow（白 10%）」**正确**（严格 9.8%，四舍五入即 10%）。

### D3 —— `HighlightListAccent*` 的 Opacity **亮暗不同**，亮色整体低 0.2

```
303:       <SolidColorBrush x:Key="SystemControlHighlightListAccentHighBrush" Color="{ThemeResource SystemAccentColor}" Opacity="0.9" />
304:       <SolidColorBrush x:Key="SystemControlHighlightListAccentLowBrush" Color="{ThemeResource SystemAccentColor}" Opacity="0.6" />
305:       <SolidColorBrush x:Key="SystemControlHighlightListAccentMediumBrush" Color="{ThemeResource SystemAccentColor}" Opacity="0.8" />

4219:       <SolidColorBrush x:Key="SystemControlHighlightListAccentHighBrush" Color="{ThemeResource SystemAccentColor}" Opacity="0.7" />
4220:       <SolidColorBrush x:Key="SystemControlHighlightListAccentLowBrush" Color="{ThemeResource SystemAccentColor}" Opacity="0.4" />
4221:       <SolidColorBrush x:Key="SystemControlHighlightListAccentMediumBrush" Color="{ThemeResource SystemAccentColor}" Opacity="0.6" />
```

**暗 0.6/0.8/0.9 → 亮 0.4/0.6/0.7。** Low 档不是本库的 0.24。
本库 `kanesumi-core/src/colors.rs:51-53`「0.24 属 Kanesumi 取值（待实测定稿）」—— 一手源的对应值是 **暗 0.60 / 亮 0.40**，二者都与 0.24 差距很大。要么按一手源取 0.60/0.40，要么明确登记为 Kanesumi 有意偏离，不能声称"待实测"。

### D4 —— `TextControlSelectionHighlightColor` 是 **不透明强调色（100%）**，不是 35%

```
864:       <StaticResource x:Key="TextControlSelectionHighlightColor" ResourceKey="SystemControlHighlightAccentBrush" />
4780:       <StaticResource x:Key="TextControlSelectionHighlightColor" ResourceKey="SystemControlHighlightAccentBrush" />
```
`SystemControlHighlightAccentBrush`（`A:282` / `A:4198`）= `<SolidColorBrush x:Key="SystemControlHighlightAccentBrush" Color="{ThemeResource SystemAccentColor}" />` —— **行内无 Opacity**。

因此该令牌 = 强调色 **100% 不透明**（非 35%、非任何降透档）。
本库 `kanesumi-core/src/colors.rs:42-47` 断言「`TextControlSelectionHighlightColor` → 强调色 **35%**」**与一手源直接冲突**。源 B 亦只转发不定义（`B:3350`），未给任何补充数值。

### D5 —— 禁用态"更弱"不由 Base*/List* 笔刷承担

`SystemControlDisabledBaseMediumLowBrush`（A:253/A:4169）与 `SystemControlDisabledListMediumBrush`（A:258/A:4174）都是**字面同值的纯转发**，行内无 `Opacity`：

```
253:       <SolidColorBrush x:Key="SystemControlDisabledBaseMediumLowBrush" Color="{StaticResource SystemBaseMediumLowColor}" />
258:       <SolidColorBrush x:Key="SystemControlDisabledListMediumBrush" Color="{StaticResource SystemListMediumColor}" />
```

故：禁用态不透明度（本库 `indicator.rs:42-43`「UWP 惯例 0.38」）**不可能**从这些笔刷推出 —— 它要么在控件模板的 `Opacity` 属性上，要么在该文件之外。`0.38` 在源 A 的 Base*/List* 族中**无一手证据**；源 A 只在 `TextControlBackground*Opacity` 处给过无关的 0.8/0.4/0.6/1（A:87,93,94,95）。

### D6 —— 「Base* 泛称」在源 A 里有 2 套，本库沿用的是 `SystemBase*` 而非 `SystemAlt*`

源 A 同时给 `SystemAltHighColor`（`A:205` 暗 `#FF000000` / `A:4121` 亮 `#FFFFFFFF`）与 `SystemBaseHighColor`，两者**方向相反**：
- `SystemBase*` = **承载色的补色**（暗→白、亮→黑）：本库要的那一套（前景/字形强度）。
- `SystemAlt*` = **承载色同侧**（暗→黑、亮→白）：面板/遮罩底色。

本库 `indicator.rs:45-58` 的「前景强度档」语义对应 **`SystemBase*`**，命名正确；但需注意 `TextControlBackground`（A:850）走的是 **`Alt*`**（`SystemAltMediumLowColor` = 暗 `#66FFFFFF` 白 40% / 亮 `#66000000` 黑 40%），与前景族不同源。

### D7 —— 源 B（WinUI 2.8.6）**不能**作为现代 Fluent 令牌的一手源

族 6 的 28 个现代令牌在 `Generic.xaml` 命中数**全为 0**，且源 B **零个 `<Color x:Key=`**。原因：WinUI 2.8.6 的 `Generic.xaml` 是控件模板文件，令牌字典（`themeresources.xaml`）随 WinUI 框架二进制分发，NuGet 包的 `lib\uap10.0\Microsoft.UI.Xaml\` 下**只有 `Themes\Generic.xaml` 一个 .xaml/.xbf 文件**（已递归枚举确认）。
若确需 WinUI 3 现代族原值，须另找源（如 WinUI 3 / Windows App SDK 包内的 `themeresources.xaml`，或 `microsoft-ui-xaml` 源码仓的 `Common_themeresources_any.xaml`）——**本任务给定的两个源都取不到**。

### D8 —— 高对比字典会**丢弃全部 alpha**

源 A 高对比块把 Base*/List*/Accent* 全部改指系统色（`SystemColorWindowTextColor`、`SystemColorHighlightColor`、`SystemColorWindowColor`、`SystemColorButtonTextColor`），Alpha 恒为不透明：

```
2061:       <SolidColorBrush x:Key="SystemControlHighlightListAccentHighBrush" Color="{ThemeResource SystemColorHighlightColor}" />
2064:       <SolidColorBrush x:Key="SystemControlHighlightListMediumBrush" Color="{ThemeResource SystemColorHighlightColor}" />
2065:       <SolidColorBrush x:Key="SystemControlHighlightListLowBrush" Color="{ThemeResource SystemColorHighlightColor}" />
2081:       <SolidColorBrush x:Key="SystemControlPageTextBaseHighBrush" Color="{ThemeResource SystemColorWindowTextColor}" />
2085:       <SolidColorBrush x:Key="SystemControlErrorTextForegroundBrush" Color="{ThemeResource SystemColorWindowTextColor}" />
```

**结论：不能把一套 alpha 档位推广到高对比。** 高对比下 Low/Medium/High 的层次差异被完全抹平 —— 这也解释了为什么 UWP 控件模板在高对比下常另写状态（如 `B:1025-1026` 的 ToggleButton `HighContrast` 分支）。

### D9 —— 源 A 的 `SystemErrorTextColor` 暗色是**黄**不是红

`A:230` `#FFF000`（黄）vs `A:4146` `#C50500`（暗红）。本库若把 `SystemErrorTextColor` 当"错误红"用于暗色，会得到黄色。暗色下 UWP 的错误强调靠**黄**（在深底上更醒目），亮色才用红。

## 第 4 节：一句话结论

族 1（`SystemBase*Color`）、族 2（`ForegroundBase*Brush`）、族 3（`SystemList*Color` + `HighlightList*Brush`）、族 4（`HighlightListAccent*`）、族 5（`SystemErrorTextColor`）**五族全部可从源 A 一次取值替换本库临时值**（族 4/5 须区分暗亮与"缺失字面量"的两处例外）；族 6（WinUI 3 现代 `TextFillColor*` / `SubtleFillColor*` / `ControlFillColor*` / `SolidBackgroundFillColor*` / `AccentFillColor*` / `TextOnAccentFillColor*` / `ControlStrokeColor*`）在源 A 与源 B **均不存在**，须另找 WinUI 3 令牌字典，本库这些项应继续挂`CANON_VS_TEMPORARY`；族 7 表明 `HighlightListLow/Medium` 与 `SystemListLow/Medium` 是同一真值的笔刷别名，改后者即改前者，且**UWP 无 30% 档**。
