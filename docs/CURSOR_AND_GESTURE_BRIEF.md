# 指针与手势：开工清单（2026-11-07 用户口述，待落地）

> 本文件先借 Kanesumi 分支的可推送通道落盘，光标工作开工时迁到 Ether 仓 `docs/`（主仓口径）。
> 用户原话要点：「光标阻尼、精准度、轻微修正、抖动变大（像 macOS），KDE 有原样可以抄，
> 但他们有个小特性似乎特意保留：一直甩就一直变大，我们不要这个，要类似 macOS 的行为」；
> 另有双指滚动、打开 Launcher 等手势。

## 一、指针（屏幕上的箭标 / 光标的运动本身）

要做的四件事，按用户表述拆：

1. **阻尼**：指针移动不是 1:1 直通，低速时细腻、高速时有一点滞后感（等价于「加速度曲线」）。
2. **精准度**：低速下的最小位移要可控（微调时不要跳格），高频事件要被正确处理而不是丢。
3. **轻微修正**：手抖时轻微向意图方向收敛（这是 macOS 手感的关键，不是单纯的平滑滤波）。
4. **抖动变大**：快速来回甩时指针增益变大（同样的手部位移，屏幕位移更大）——**但有上限**。

### 关键取舍（用户明确定过）

- KDE 的参考实现可以抄，**但不要「一直甩就一直变大」**那条：KDE 的增益在连续甩动时会持续累积，
  用户点名不要这个行为。要 macOS 式：增益随速度上升，**到顶就不再涨**，减速后回落。
- 也就是说增益是「速度的函数」，不是「累积量的函数」。实现上必须是无记忆的映射 +
  有界平滑，不能写成累加器。

### 落地位置与既有相关件

- 合成器：`compositor/src/pointer.rs`（软件光标），硬件光标走 cursor plane（`cur1`）。
- 交互常量：`kanesumi-core::interaction`（双击容差、拖拽阈值、触控阈值的唯一真源）。
- 现成正典：`docs/INTERACTION_CANON.md` §Ⅱ 指针；`docs/FEEL_PLAN.md`（体感主线，含触控板惯性、
  半速换算、指点杆独立档）。
- 注意：正典里已有「拖拽阈值 4 px、双击容差 ±2 px」等值，指针增益与滤波参数**要新开一节**写清，
  不要塞进现有节里改语义。

## 二、手势（触控板 / 触摸屏）

1. **双指滚动**：连续像素、惯性（松手后按末端速度衰减）、方向与「自然滚动」开关。
   已知缺口：libinput 的 `axis_stop` 未接，故惯性收尾不干净（`docs/FEEL_PLAN.md` 已记）。
2. **打开 Launcher**：三指上滑已在 `docs/GESTURE_PLAN.md`（裁定 §129）里定过：
   `kanesumi-core::snap_tracker` 命名进度源 + 跟手 / 投影选点 / 解析弹簧落定 / 可打断；
   协议 v3 图层按进度绑定；Super 键是同一进度源的无手指特例。
3. **手势与指针的分界**：手势期间指针不应参与命中（否则滑到 Dock 上会误触）。

## 三、开工前必须先做的两件事

1. 读 `docs/FEEL_PLAN.md` + `docs/GESTURE_PLAN.md` + `INTERACTION_CANON.md` §Ⅱ，确认哪些已裁定、
   哪些是待定；本文件里的「增益上限」属新增裁定，落地时要补进 `DECISIONS_*.md`。
2. 量尺先行：指针的「手感」没有量就只会来回试。至少要先能记录
   「输入事件时间戳 → 光标位置」序列（写 `~/.local/state/`，参 AGENTS.md 排障铁律：不进 `/tmp`），
   否则阻尼 / 修正 / 增益都只能靠主观描述调参。

## 四、与当前在推的工作的关系

- 与菜单（`docs/MENU_REFERENCE.md`）、表格行（`CONTROL_SPEC.md` §51）无耦合，可并行。
- 面板迁移（另一会话）动的是 settings 侧面板内容，不碰 `compositor/src/pointer.rs`。
- 部署仍按用户裁定：全部改完一次性推 e495。
